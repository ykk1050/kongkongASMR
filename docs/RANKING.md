# 랭킹 붙이기 — 구글 스프레드시트

기록을 모으는 곳은 **구글 스프레드시트**, 게임과 시트 사이의 창구는 그 시트에 붙인
**Apps Script 웹 앱**입니다. 서버를 따로 빌리지 않아도 되고, 기록은 선생님 계정의
시트 안에만 쌓입니다.

설정하지 않아도 게임은 그대로 돌아갑니다. 그때는 기록이 그 기기 안에만 남고,
랭킹 화면이 "아직 설정되지 않았다"고 알려 줍니다.

준비물은 구글 계정 하나, 걸리는 시간은 10분쯤입니다.

---

## 1. 스프레드시트 만들기

1. [sheets.new](https://sheets.new) 로 빈 시트를 하나 만듭니다.
2. 이름을 알아보기 쉽게 바꿉니다 — 예: `소리 콩콩 랭킹`.

시트 안을 미리 꾸밀 필요는 없습니다. 3번에서 스크립트가 알아서 만듭니다.

## 2. Apps Script 붙이기

1. 시트 메뉴에서 **확장 프로그램 → Apps Script**.
2. 열린 편집기의 `Code.gs` 내용을 **전부 지우고**, 이 저장소의
   [`apps-script/Code.gs`](../apps-script/Code.gs) 를 통째로 붙여 넣습니다.
3. 💾 저장.

## 3. 시트 준비하기

1. 스프레드시트 탭으로 돌아가 **새로고침**합니다.
   상단에 **소리 콩콩 랭킹** 메뉴가 생깁니다.
2. **소리 콩콩 랭킹 → 시트 준비하기** 를 누릅니다.
3. 처음 한 번은 구글이 권한을 묻습니다.
   **고급 → (프로젝트 이름)(으)로 이동 → 허용** 으로 승인합니다.
   (내가 만든 스크립트가 내 시트를 고치는 것이라 안전합니다.)
4. `기록` 시트가 생기고 머리글이 채워지면 성공입니다.

## 4. 웹 앱으로 배포하기

Apps Script 편집기에서 오른쪽 위 **배포 → 새 배포**.

| 항목 | 고를 값 |
|---|---|
| 유형 | **웹 앱** |
| 설명 | 아무거나 (예: `v1`) |
| 다음 사용자로 실행 | **나** |
| 액세스 권한이 있는 사용자 | **모든 사용자** |

> **"모든 사용자"가 맞습니다.** 아이들은 구글 로그인 없이 게임에 들어오기 때문에,
> "Google 계정이 있는 모든 사용자"로 두면 기록이 저장되지 않습니다.
> 이 주소로 할 수 있는 일은 이 스크립트가 허용한 것(기록 등록·순위 조회)뿐이고,
> 시트 자체가 공개되는 것은 아닙니다.

**배포** 를 누르면 나오는 **웹 앱 URL** 을 복사합니다.
`https://script.google.com/macros/s/AKfy…/exec` 처럼 `/exec` 로 끝납니다.

## 5. 게임에 주소 적기

[`js/ranking-config.js`](../js/ranking-config.js) 를 열고 복사한 주소를 넣습니다.

```js
window.SK_RANKING = {
  endpoint: 'https://script.google.com/macros/s/AKfy…/exec',
  enabled: true
};
```

깃허브에 올리면(push) 몇 분 안에 웹에 반영됩니다.
브라우저가 옛 파일을 들고 있을 수 있으니 `Ctrl+Shift+R` 로 강력 새로고침해서 확인하세요.

## 6. 확인하기

1. 게임에서 한 판 하고 일부러 목숨을 다 잃습니다.
2. 게임 오버 화면에서 닉네임을 넣고 확인란에 체크한 뒤 **랭킹 등록**.
3. "랭킹에 올랐어요 — 점수 N위!" 가 뜨고 순위표가 열리면 끝입니다.
4. 스프레드시트 `기록` 시트에도 한 줄이 늘어나 있어야 합니다.

잘 안 되면 Apps Script 편집기에서 **소리 콩콩 랭킹 → 자체 점검** 을 눌러
토큰 발급과 시트 연결이 정상인지 먼저 확인하세요.

---

## 코드를 고친 뒤에는

`Code.gs` 를 고쳤다면 **배포 → 배포 관리 → ✏️ 편집 → 버전: 새 버전 → 배포** 를
해야 반영됩니다. 이렇게 하면 **주소는 그대로**라 `ranking-config.js` 는 건드릴 필요가
없습니다. (`새 배포`를 다시 누르면 주소가 바뀌어 버립니다.)

## 시트 관리

`기록` 시트의 한 줄이 한 판입니다.

| 칸 | 내용 |
|---|---|
| 시각 | 등록된 시각 |
| 닉네임 | 아이가 적은 이름 |
| 점수 · 시간(ms) · 시간 | 최종 점수, 논 시간 |
| 맞힌문제 | 끝까지 푼 문제 수 |
| 정답밟기 · 오답밟기 · 낙하 | 검증에 쓰는 값 |
| 밟기정확도 | 정답밟기 ÷ (정답밟기+오답밟기) — 글자 한 장 단위 (랭킹 지표) |
| 문제수 · 격자 | 받아 본 문제 수, 판 크기 |
| **공개** | **TRUE 인 줄만 랭킹에 나옵니다** |
| 비고 | 공개가 FALSE 인 이유 |
| 실행ID | 같은 판이 두 번 등록되지 않게 하는 표식 |
| 시도문제 | 글자를 한 번이라도 밟은 문제 수 |
| 정답률 | 맞힌문제 ÷ 시도문제 |
| 단원별 | `선사·고조선:34/28|삼국·가야:31/25` — `단원:시도/맞힘` 을 `|` 로 이어 붙인 것 |

> **칸 순서는 뒤에만 덧붙입니다.** 가운데에 끼워 넣으면 이미 쌓인 기록의 칸이
> 통째로 어긋납니다. 시도문제·정답률·단원별이 맞힌문제 옆이 아니라 맨 뒤에 있는
> 이유입니다. 스크립트를 새로 붙여 넣으면 머리글은 알아서 최신으로 맞춰집니다.

- **부적절한 닉네임을 내리려면** 그 줄의 `공개` 를 `FALSE` 로 바꾸세요.
- **검사에 걸린 기록을 살리려면** `공개` 를 `TRUE` 로 바꾸세요.
- 바꾼 뒤 바로 반영하려면 **소리 콩콩 랭킹 → 랭킹 다시 계산**.
  (그냥 두어도 1분 안에 저절로 반영됩니다.)
- 학기를 새로 시작하려면 2행부터 전부 지우면 됩니다.

## 랭킹은 이렇게 매깁니다

집계 조건은 **단원 × 지표** 두 단으로 고릅니다.

| 지표 | 무엇을 겨루나 | 집계 | 참가 조건 |
|---|---|---|---|
| 점수 | 한 판에서 정답을 얼마나 연달아 맞혔나 | **한 판 최고** | 없음 |
| 맞힌 문제 | 끝까지 푼 문제가 몇 개인가 | 모든 판 누적 | 없음 |
| 시도 문제 | 얼마나 많이 도전했나 | 모든 판 누적 | 없음 |
| 정답률 | 시도한 문제 중 몇 %를 맞혔나 | 모든 판 누적 | **시도 30문제 이상** |
| 밟기 정확도 | 밟은 타일 중 순서에 맞았던 비율 | 모든 판 누적 | **시도 30문제 이상** |

**정답률**이 '내용을 아는가'라면 **밟기 정확도**는 '발을 정확히 디뎠는가'에
가깝습니다. 답을 알아도 대각선 점프가 서툴러 엉뚱한 타일을 밟으면 내려가고,
조작이 능숙하면 답을 몰라도 올라갑니다. 두 값을 나란히 보면 아이가 막힌 곳이
내용인지 조작인지 구분됩니다.

**단원**(선사·고조선 / 삼국·가야 / 생활·문화)을 고르면 그 단원의
**맞힌 문제**와 **정답률**만 남습니다. 둘 다 **그 단원을 30문제 이상 시도한
사람**만 순위에 들어갑니다. 점수·시도 문제·밟기 정확도는 단원별로 나누지 않습니다.

네 지표 모두 **높은 순 · 낮은 순** 으로 볼 수 있습니다.
화면에는 **100위까지** 보여 주고, 그 아래는 **닉네임 검색**으로 찾습니다.
값이 같으면 **먼저 세운 사람이 위**입니다.

### 왜 점수만 '한 판 최고'인가

점수는 한 판 안에서 콤보를 얼마나 이어 갔는지를 보는 값이라 판마다 따로 재는 게 맞습니다.
반면 시도·맞힘·정답률은 "얼마나 많이, 얼마나 정확하게 공부했는가"를 보는 값이라
판을 쪼개 세면 뜻이 흐려집니다. 짧게 한 판 잘 본 것보다 꾸준히 많이 푼 쪽이
위로 가야 교실에서 맞습니다.

### 왜 30문제인가

정답률은 적게 풀수록 튀기 쉽습니다. 3문제 중 3개를 맞힌 100%가
100문제 중 92개를 맞힌 92%보다 위로 가면 줄을 세우는 뜻이 없어집니다.
30문제는 우리 문제집(50문항)의 절반을 조금 넘는 수라, 한두 판 성실히 풀면
닿는 선이면서 요행으로는 채우기 어려운 선입니다.

문제는 언제나 전체에서 무작위로 나오므로(단원을 골라 풀 수 없습니다),
한 단원에서 30문제를 시도하려면 전체로 75~100문제쯤 풀어야 합니다.
여러 판에 걸쳐 누적되니 하루에 다 채울 필요는 없습니다.

바꾸고 싶으면 **두 곳을 같이** 고쳐야 합니다 —
`apps-script/Code.gs` 의 `GATE` 와 `js/ranking.js` 의 `GATE`.

### 시도 문제는 어떻게 세나

**글자를 한 번이라도 밟은 문제**만 셉니다. 받아 본 문제를 세면
'다음 문제'만 계속 눌러 숫자를 부풀릴 수 있기 때문입니다.
한 문제에서 여러 번 틀려도 시도는 **1회**이고, 밟아 보고 못 푼 채 넘긴 문제는
시도에는 들어가되 맞힘에는 안 들어가 정답률이 내려갑니다.

### 버틴 시간은 왜 없나

제한 시간이 없는 게임이라 켜 두기만 해도 늘어납니다. 줄을 세울 수 있는 값이
아니라서 조건에서 뺐습니다. 다만 기록(시트)에는 그대로 남고,
'시간에 비해 점수가 너무 높지 않은가' 같은 검사에는 계속 쓰입니다.

## 개인정보

닉네임은 누구나 보는 목록에 그대로 올라갑니다. 그래서 두 겹으로 막습니다.

1. **기계가 알아볼 수 있는 것은 거른다** — 이메일, 전화번호, 주민등록번호 꼴,
   학년·반·번호, 긴 숫자. 게임과 서버 양쪽에서 각각 검사합니다.
2. **나머지는 본인이 확인하게 한다** — 사람 이름은 기계가 가려낼 수 없습니다
   ("홍길동"과 "달려라곰"은 구별되지 않습니다). 그래서 등록 화면에 경고문을 두고,
   확인란에 체크해야만 등록 버튼이 켜집니다.

수업 전에 한 번 짚어 주시면 좋습니다 — **닉네임에는 이름 대신 별명을 쓰기.**

## 조작 방지 — 무엇을 막고, 무엇은 못 막나

> 기준은 전부 실제 플레이의 **두세 배로 넉넉하게** 잡혀 있습니다.
> 잘하는 아이가 억울하게 걸리는 쪽이 부정행위가 한 건 지나가는 쪽보다 나쁘기 때문입니다.

**막는 것**

| 시도 | 어떻게 막히나 |
|---|---|
| 콘솔에서 `점수 = 999999` | 점수·목숨·시간은 클로저 안에만 있어 바깥에서 닿지 않습니다 |
| 개발자 도구의 테스트용 훅으로 판 조작 | 훅은 `localhost` 와 `?debug=1` 에서만 열리고, 쓰면 그 판은 비공식으로 표시됩니다 |
| 네트워크 탭에서 요청의 숫자만 고쳐 다시 보내기 | 서명이 어긋나 거부됩니다 |
| 등록 주소를 직접 만들어 호출 | 서버가 발급한 실행 토큰이 없으면 거부됩니다 |
| 한 판을 여러 번 등록 | 실행 토큰은 1회용입니다 |
| 5초에 300문제 같은 기록 | 시간·점수·문제 수의 앞뒤가 맞는지 검사합니다 |

**못 막는 것**

게임 파일을 통째로 복사해 고친 사람은 서명도 다시 만들 수 있습니다.
브라우저에서 도는 코드는 원래 그렇습니다. 그래서 마지막 방어선은 서버의
타당성 검사이고, 그마저 통과한 기록은 시트에서 선생님이 보고 판단하시면 됩니다.

**걸린 기록도 지우지 않습니다.** 시트에 그대로 남고 `공개` 칸만 `FALSE` 가 되며,
`비고` 에 이유가 적힙니다. 정상인데 걸렸다면 `공개` 를 `TRUE` 로 바꾸면 바로 올라갑니다.

## 왜 JSONP 인가

Apps Script 웹 앱은 `/exec` 요청을 `script.googleusercontent.com` 으로 넘깁니다.
그래서 `fetch` 로 부르면 브라우저나 배포 설정에 따라 CORS 에서 막히는 경우가 생깁니다.
교실에서 여러 기기로 접속할 때 "어떤 기기는 되고 어떤 기기는 안 되는" 것이 가장 나쁘므로,
CORS 를 아예 타지 않는 `<script>` 호출(JSONP)로 통일했습니다.
주고받는 값이 닉네임과 숫자 몇 개뿐이라 주소 길이도 문제가 되지 않습니다.
