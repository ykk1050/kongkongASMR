# 오디오 에셋 매핑 가이드

> 구현: `js/audio.js` · 매니페스트: `assets/audio/manifest.json`

---

## 0. 요약

이 게임은 **오디오 파일 0개로도 완전히 동작**합니다. 모든 소리가 Web Audio API로
실시간 합성되기 때문입니다. `assets/audio/manifest.json`에 파일을 등록하면
해당 키의 합성음이 샘플로 **대체**되고, 등록하지 않은 키는 계속 합성음을 씁니다.
즉 **부분 교체가 가능**합니다.

현재 12종 중 **8종은 실제 녹음**을, 4종은 합성음을 씁니다.

| | 재질 |
|---|---|
| 녹음 | 키캡 · 나무 · 젤리 · 에어캡 · 슬라임 · 낙엽 · 모래 · 눈 |
| 합성 | 솜 · 구슬볼 · 유리구슬 · 스펀지 |

녹음 쪽은 재질마다 변형을 4~5개씩 두고 밟을 때마다 번갈아 재생합니다.
같은 파일이 반복되면 ASMR이 아니라 '녹음 재생'으로 들리기 때문입니다.

## 1. 합성 모형

v2부터 **모달 합성(modal synthesis)** 을 씁니다. 두드린 물체의 소리는
"고유 주파수에서 각자 다른 속도로 감쇠하는 사인 모드의 합"입니다.
단일 오실레이터로는 절대 나오지 않는 재질감이 여기서 나옵니다.

모든 타격음은 **트랜지언트 / 바디 / 테일** 3단으로 나뉩니다.

| 단계 | 역할 | 구현 |
|---|---|---|
| 트랜지언트 | 표면이 닿는 순간의 딱·톡 | 3~16ms 노이즈 버스트 (하이패스/밴드패스) |
| 바디 | 물체의 공명 = 재질의 정체 | `modalVoice()` — 비조화 모드 3~5개 |
| 테일 | 결·부스러짐·잔향 | `granular()` 미세 알갱이 + 컨볼루션 잔향 |

재질별 모드비(첫 모드를 1로 둔 비율):

| 재질 | 기본 주파수 | 모드비 | 감쇠 |
|---|---|---|---|
| 키캡 | 205Hz | 1 : 1.93 : 3.41 | **38ms** (짧아야 '딸깍') |
| 나무 | 132Hz | 1 : 2.14 : 3.87 | **82ms** |
| 솜 | 76Hz | 1 : 1.73 | 240ms (어택 14ms) |
| 유리구슬 | 880Hz | 1 : 2.45 : 4.11 : 6.83 | 950ms (가장 김) |
| 구슬볼 | 420~980Hz 무작위 | 알마다 독립 모드 5~9개 | 50~110ms |
| 정답 종 | 펜타토닉 | 1 : 2.76 : 5.40 : 8.93 | 750ms |

### ⚠ 합성에서 하지 말아야 할 것 (전부 실제로 겪은 실패)

| 하면 안 되는 것 | 어떻게 들리나 | 대신 |
|---|---|---|
| 모달에 LFO 비브라토 | 곧바로 **전자음/신스**가 된다 | `toneVoice` 의 피치 글라이드로 출렁임을 만든다 |
| 타격음의 모달 감쇠를 100ms 이상 | 음정이 들려 **북·마림바**가 된다 | 40~90ms로 강하게 감쇠 |
| 처프에 Q 12 이상 | **휘파람·새소리**가 된다 | Q 4~6의 넓은 크리크 |
| 사각거림을 이산 알갱이로만 | **지직거리는 노이즈**가 된다 | 연속 노이즈를 깔고 굵은 알갱이만 얹는다 |

**젤리·슬라임**은 모달을 쓰지 않습니다. 젤리는 300→98Hz 피치 글라이드,
슬라임은 공명 로우패스(Q 5~6)가 열렸다 닫히는 왕복으로 만듭니다.
이 왕복이 '찌걱'의 정체입니다.

**공명이 없는 재질**(낙엽·모래·눈·에어캡)은 `granular()` 가 주역입니다.
수십 개의 알갱이를 시간(앞쪽에 몰리게)·주파수·좌우로 흩뿌립니다.
모래는 연속 노이즈 두 겹 + 굵은 알갱이 9알, 눈은 크리크 9회 + 알갱이 16알을 씁니다.

**삐걱이는 재질**(눈·스펀지)은 `squeak()` 를 씁니다.
Q 4.5의 **넓은** 대역이 위로 쓸려 올라가며 여러 번 끊기는 크리크입니다.
Q를 높이면 휘파람이 되므로 절대 올리지 마세요.

**휴머나이즈** — 매 타격마다 피치 ±3%, 모드별 ±1.2%, 알갱이 게인 0.35~1.15배,
노이즈 버퍼 읽기 위치가 전부 무작위로 흔들립니다. 같은 타일을 연달아 밟아도 같은 소리가 나지 않습니다.

## 1.5 시그널 체인

```
  각 사운드 보이스
        │
        ▼
  ┌───────────────┐   x = 화면상 캐릭터 좌우 위치(-3.2 ~ +3.2)
  │  PannerNode   │   z = -1.4 - depth*3.0   (멀수록 뒤로)
  │ HRTF, inverse │   ← 바이노럴 정위
  └───────┬───────┘
          ├────────────▶ dryBus ─────────────────────┐
          │                                           ▼
          └──▶ sendGain ──▶ wetBus(0.16) ──▶ Convolver(IR 0.85초, 어둡게)
                                                      │
                          preMaster ◀─────────────────┘
                     (DRIVE 1.05)
                              │
                     lowShelf(180Hz +3.5dB, 근접 마이크 감각)
                              │
                     Compressor(-14dB, ratio 6) ← 겹칠 때만 부드럽게 제어
                              │
                     SoftClip(knee 0.65, tanh) ← 어택이 놓친 트랜지언트 안전망
                              │
                     masterGain(1.0, 음소거 페이드 전용) ──▶ destination / Analyser
```

- **그래뉼러 확산:** `spatialTrio()` 가 좌·중·우 세 갈래 패너를 만들어
  알갱이를 흩뿌립니다. 낙엽을 밟으면 머리 주변을 감싸는 느낌이 납니다.
- **잔향이 짧고 어두운 이유:** ASMR은 "가까이서" 들려야 합니다.
  초기 반사 4개를 심은 0.85초 IR을 로우패스로 어둡게 깎았습니다.

- **바이노럴:** `PannerNode.panningModel = 'HRTF'`. 리스너는 원점에서 −Z를 바라봅니다.
  캐릭터가 화면 왼쪽에 있으면 왼쪽 귀에서, 오른쪽에 있으면 오른쪽 귀에서 들립니다.
  `SK.Game.panOf(gx, gy)`가 카메라 기준 화면 x를 −1~+1로 정규화해 넘깁니다.
- **잔향:** 지수 감쇠 노이즈로 임펄스 응답을 즉석 생성 — 작은 방 느낌. 외부 IR 파일 불필요.
- **레벨 미터:** 마스터에 `AnalyserNode`가 붙어 있고 `SK.Audio.getLevel()`이 RMS를 0~1로 돌려줍니다.
  캐릭터 주변 오라 링과 헤드폰 이어컵 발광이 **실제 출력 레벨**에 맞춰 맥동합니다 —
  소리와 화면이 코드 수준에서 묶여 있는 지점입니다.
  음량 밸런스를 잴 때도 이 값을 씁니다(6장).

### 2.1b 도약 · 파괴

| 키 | 언제 울리나 | 합성 설계 | 녹음 가이드 |
|---|---|---|---|
| `hop_whoosh` | 타일에서 도약할 때 | 밴드패스 노이즈 1100→2800Hz(큰 점프는 700→2000Hz, 더 길게) | 짧은 바람 소리. 100~220ms |
| `crack_leaf` | 낙엽에 금이 갈 때(1단계) | 하이패스 노이즈 틱 4~9개를 90ms에 산포 + 210→150Hz 삼각파 | 마른 잎이 갈라지는 한 번 |
| `crack_bubble` | 에어캡 알이 하나 터질 때 | 760→2200Hz 사인 26ms + 3.6kHz 하이패스 | 뽁뽁이 한 알 |
| `shatter_leaf` | 낙엽이 완전히 부서질 때 | 재질음 + 하이패스 노이즈 12발 + 120→70Hz 저역 | 한 줌을 으스러뜨리는 소리 |
| `shatter_bubble` | 에어캡이 완전히 터질 때 | 팝 7발 + 노이즈 + 저역 | 여러 알이 연속으로 |

> 균열음은 단계가 올라갈수록 재생속도가 `0.92 + (stage/total)×0.5` 배로 높아집니다.
> 단계별로 따로 녹음할 필요 없이 **한 번만** 녹음하면 됩니다.

### 소모성 타일은 재질음을 바탕에 깐다

낙엽·에어캡·모래·눈·구슬볼은 밟을 때마다 `step` 이 아니라 `crack` 또는 `shatter` 로
빠집니다. 그래서 예전에는 **재질 고유의 소리가 게임에서 한 번도 나지 않았고**,
소리 도감(`preview` → `step`)에서 듣던 소리와 실제 타일 소리가 서로 달랐습니다.

지금은 `crack` / `shatter` 가 먼저 `step_<재질>` 을 재생하고 그 위에 균열·파괴음을
얹습니다. `crack_<재질>` 이나 `shatter_<재질>` 샘플을 따로 등록하면 그쪽이 우선합니다.

### 2.2 퀴즈 피드백

| 키 | 언제 울리나 | 합성 설계 | 녹음 가이드 |
|---|---|---|---|
| `quiz_wrong` | 순서를 틀렸을 때 | 128→64Hz 사인 + 96→58Hz 삼각파 + 520Hz 로우패스 썩 | 0.3초 내외의 둔탁한 thud. 불쾌하지 않게, 저역 중심 |

> **정답에는 소리를 쓰지 않습니다.** 예전에는 맑은 종소리(`quiz_step`)와 상승
> 아르페지오(`quiz_solve`)가 울렸는데, 이 게임에서 가장 잘 들려야 할 발소리 ASMR을
> 통째로 덮어 버렸습니다. 지금은 정답 피드백을 귀가 아니라 눈으로 줍니다 —
> `Particles.solveMark()` 가 정답 칸 위에 도장을 찍습니다.

### 2.3 대체 불가(항상 합성)

|---|---|

## 3. 매니페스트 사용법

`assets/audio/manifest.json`:

```json
{
  "basePath": "assets/audio/",
  "samples": {
    "step_leaf": "leaf_crunch.wav",
    "step_snow": ["snow_1.wav", "snow_2.wav", "snow_3.wav"],
    "step_wood": { "files": ["wood_1.wav", "wood_2.wav"], "gain": 0.32 }
  }
}
```

값은 세 가지 형태를 씁니다.

| 형태 | 뜻 |
|---|---|
| 문자열 | 그 키를 파일 하나로 대체 |
| 배열 | **변형**. 재생할 때마다 다른 파일이 쓰이며, 같은 것이 연달아 나오지 않습니다 |
| `{ files, gain }` | 변형에 더해 그 키에만 게인 보정 |

- 값이 `http(s)://`, `/`, `assets/`로 시작하면 그대로 쓰고, 아니면 `basePath`를 앞에 붙입니다.
- **파일이 없거나 디코딩에 실패해도 조용히 무시**되고 합성음이 그대로 쓰입니다(게임은 멈추지 않습니다).
- 적용된 키는 콘솔에 `[audio] 샘플 에셋 적용: step_snow×5, …` 처럼 변형 개수와 함께 찍힙니다.
- `samples`가 비어 있으면 네트워크 요청 자체를 하지 않습니다.
- `step_<재질>_stomp` 이 없으면 강하게 내려찍을 때도 `step_<재질>` 를 더 크게 재생합니다.
  (예전에는 합성음으로 떨어져, 같은 타일인데 세게 밟으면 재질이 바뀐 것처럼 들렸습니다.)

코드에서 직접 등록할 수도 있습니다:

```js
SK.Audio.registerSampleMap({ step_jelly: ['assets/audio/jelly_1.wav', 'assets/audio/jelly_2.wav'] })
  .then(loaded => console.log('적용됨:', loaded));
```

### 게인은 왜 따로 필요한가

녹음은 파일마다 마이크 거리와 압축이 달라서, 파형 레벨을 맞춰도 게임 안에서는
체감 음량이 3배까지 벌어집니다. 그래서 `manifest.json` 의 `gain` 은
**게임에서 직접 재어 정한 값**입니다. 재는 방법은 6장에 있습니다.

## 4. 녹음 규격

| 항목 | 권장값 |
|---|---|
| 포맷 | WAV(PCM 16/24bit) 또는 OGG. 브라우저 `decodeAudioData` 지원 형식 |
| 샘플레이트 | 48kHz (44.1kHz도 무방 — 브라우저가 리샘플링) |
| 채널 | **모노**. 정위는 엔진의 HRTF 패너가 담당하므로 스테레오 소스는 정위가 흐려집니다 |
| 길이 | 딱딱한 재질 100~150ms · 푹신하거나 부서지는 재질 300~500ms |
| 레벨 | 피크 −6dBFS. 발소리는 초당 3~4회 겹쳐 울리므로 여유가 필요합니다 |
| 전처리 | 앞뒤 무음 제거(중요 — 지연으로 들립니다), DC 오프셋 제거, 룸톤 최소화 |
| 잔향 | **드라이하게**. 엔진이 컨볼루션 잔향을 별도로 겁니다 |

## 5. 강도·피치 변조 규칙 (샘플에도 그대로 적용)

```js
// 착지 강도 — 도약 높이 + 연속 도약 체인
intensity = min(1, (power > 1 ? 0.95 : 0.45) + chain * 0.07)
intensity = min(1, intensity * 1.35 + 0.25)          // 큰 점프(stomp)일 때
playbackRate = (0.88 + intensity * 0.34) * (stomp ? 0.82 : 1)
gain         = 0.5 + 0.5 * intensity
```

즉 **연속으로 빠르게 뛸수록 높고 크게**, 큰 점프 착지는 더 낮고 묵직하게 울립니다.
샘플을 쓸 때도 이 배속·게인이 그대로 곱해지므로, 피치 변화가 자연스러운 소재를 고르세요.

## 6. 음량 밸런스

재질마다 주파수 분포가 달라 **같은 게인이 같은 크기로 들리지 않습니다.**
녹음도 마찬가지여서, 파형 레벨을 맞춰 놓아도 게임 안에서는 체감 음량이 크게 벌어집니다.

### 피크 미터로 재면 안 된다 — 실제로 겪은 실패

예전에는 `getLevel()`(화면 연출용 피크 미터)로 재서 12종을 "1.38배 안에 맞췄다"고
적어 두었습니다. **틀린 측정이었습니다.** 피크는 트랜지언트를 과대평가합니다.
나무처럼 '탁' 하고 끝나는 소리는 꼭짓점만 높고 에너지는 적은데, 피크 미터는 그걸
크다고 읽습니다. 그 잣대로 맞춰 놓은 결과 실제 체감 음량은 **13.9dB** 어긋나 있었고,
나무·눈·슬라임은 키캡보다 14dB 작게 들렸습니다.

지금은 방송 표준 **BS.1770 K-가중 라우드니스**로 잽니다. 고역 셸빙(+4dB @1.68kHz)
→ 하이패스(38Hz)를 거친 뒤 평균 전력을 재고, 창은 **온셋부터 250ms**입니다
(짧은 타격음의 청각 적분 시간). 트리거 시점이 아니라 소리가 실제로 시작한
지점부터 재야 짧은 소리가 앞의 무음 때문에 부당하게 작게 나오지 않습니다.

### 보정이 걸리는 두 곳

| 소리의 출처 | 보정하는 곳 |
|---|---|
| 합성음 | `js/audio.js` 각 레시피의 기본 게인 `g` |
| 녹음 | wav 파일 자체(-20 LU 정규화) + `assets/audio/manifest.json` 의 `gain` |

녹음은 **파일 단계에서 이미 -20 LU로 정규화**되어 있습니다
(`python tools/prep-steps.py normalize --apply`). 그런데도 매니페스트에 gain이 남아
있는 이유는, 파일 레벨이 같아도 **게임 체인을 통과하면 체감이 달라지기** 때문입니다 —
저역 셸빙은 저역이 많은 재질만 키우고, 컨볼루션 잔향은 지속음이 긴 재질에 에너지를
더 얹고, 컴프레서는 피크가 뾰족한 재질을 더 많이 눌러 버립니다. 그래서 파일은
파일대로 맞추고, 게임 안 체감은 게임 안에서 다시 잽니다.

### 재는 방법

브라우저 콘솔에서 한 줄입니다.

```js
await SK.Audio.loudnessTable();   // 12종을 재서 큰 것부터. LU = 가장 큰 것 대비 dB
```

돌려주는 각 행의 `suggest` 가 **그 재질에 곱하면 최상위와 같아지는 값**입니다.
녹음이면 `manifest.json` 의 `gain` 에, 합성음이면 레시피의 `g` 에 곱하세요.
헤드룸도 함께 확인합니다.

```js
SK.Audio.peak();                  // 마스터 출력의 순간 피크(0~1)
```

wav 파일 쪽 라우드니스는 오프라인에서 봅니다.

```bash
python tools/prep-steps.py report
```

> 측정은 브라우저 패널이 **화면에 떠 있는 상태**에서 하세요.
> 가려져 있으면 게임 루프와 미터가 함께 느려져 값이 엉뚱하게 나옵니다.

### 현재 상태

| | 값 |
|---|---|
| wav 파일 라우드니스 | 전 재질 -20 LU (퍼짐 **3.0dB** — 피크 천장 0.95에 먼저 걸린 눈·나무·에어캡) |
| 게임 안 체감 퍼짐 | **5.5dB** (예전 13.9dB) |
| 11종 | 3.4dB 안에 들어옴 |
| 키캡만 -5.5dB | 60ms짜리 순수 트랜지언트라 더 밀면 '딸깍'이 뭉개진다. 여기서 멈춘 것 |
| 실측 출력 피크 | 보통 0.81 · 가장 센 내려찍기 0.94 (클리핑 없음) |

### 왜 그냥 다 키우지 않았나

체인 끝의 실측 피크가 이미 0.8~0.9입니다. 예전에는 세게 내려찍을 때 **1.10까지 올라가
하드 클리핑(지직)** 이 났습니다. `DynamicsCompressor` 는 어택이 3ms라 진짜 트랜지언트를
그냥 통과시키기 때문입니다. 그래서 체인 끝에 **소프트 클리퍼**를 하나 두었습니다
(0.65 아래는 무손실, 그 위만 tanh로 접어 ±2.0 입력까지 1.0 안에 가둠).
전체 드라이브는 `DRIVE` 로 올리되, 반드시 이 클리퍼 **앞**에 걸어야 합니다.

게인 숫자 자체는 재질끼리 비교할 수 없습니다. 모래·눈·낙엽의 합성 `g` 가 유난히 큰 것은
그 값이 **여러 겹의 노이즈와 알갱이에 나뉘어 들어가기** 때문입니다.

## 6.2 녹음을 '한 걸음'으로 자르기

긴 발소리 녹음을 눈대중으로 자르면 이런 일이 생깁니다 — 실제로 있었던 일입니다.

| 증상 | 원인 |
|---|---|
| 한 번 밟았는데 **두세 번** 소리가 난다 | 한 조각 안에 걸음이 둘 이상 들어갔다 (예전 `sand_1`) |
| 밟고 나서 **조금 뒤에** 소리가 난다 | 조각 앞에 120ms쯤 빈 구간이 붙어 있었다 (예전 `sand_3`) |
| 소리가 **툭 끊긴다** | 꼬리를 페이드 없이 잘랐다 |

`tools/prep-steps.py slice` 가 세 가지를 한꺼번에 처리합니다.

```bash
# mp3는 먼저 모노 44.1kHz wav로
ffmpeg -i source.mp3 -ac 1 -ar 44100 -c:a pcm_s16le src.wav

python tools/prep-steps.py slice src.wav sand 5 --min 320
python tools/prep-steps.py normalize --apply
```

하는 일:

1. 가장 조용한 300ms를 잡음 프로파일로 삼아 **스펙트럼 차감** (야외 녹음의 룸톤·도시
   소음이 알갱이 사이에 깔려 있으면 ASMR이 아니라 '녹음 재생'으로 들립니다)
2. **온셋 검출** — 발이 닿는 순간을 찾아 그 앞 20ms부터 자릅니다
3. 꼬리가 잦아들 때까지, 단 **다음 걸음을 침범하지 않는 선**까지만
4. 앞 6ms 페이드인 + 끝 110ms 코사인 페이드아웃 + DC 오프셋 제거
5. 크레스트 24dB 초과(알맹이 없이 튀기만 하는 조각)와 앞머리가 시끄러운 조각은 버림
6. 남은 것 중 에너지가 큰 순서로 고르되, **원본에서 서로 떨어진 걸음**이 섞이도록 분산

주요 옵션: `--rel`(온셋 문턱, 낮출수록 많이 찾음) · `--min`/`--max`(조각 길이 ms) ·
`--head`(앞머리 허용 잡음) · `--max-crest`.


## 6.5 소리 ↔ 시각 대응표

모든 사운드는 짝이 되는 시각 효과를 함께 냅니다. 사운드를 추가하면 여기도 함께 추가하세요.

| 사운드 | 시각 효과 |
|---|---|
| `step(mat)` | `Particles.stepBurst()` — 재질 색 파문 링 + 먼지, 타일 표면 발광(`t.flash`) |
| `step(..., stomp)` | 위 + 흰색 큰 링 + `쿵!` 텍스트 + 카메라 흔들림 |
| `crack(mat, stage)` | `Particles.crackBits()` + 타일 위 균열선 누적 |
| `crack('bubble', …)` | `Particles.bubblePop()` — **금이 가지 않는다.** 밟을 때마다 알 2개가 제자리에서 터진다 |
| (정답) | `Particles.solveMark()` — 정답 칸에 찍히는 도장. 소리 없음 |
| `shatter(mat)` | `Particles.shatter()` — 파편 + `CRUNCH!` + 타일 소멸 |
| `shatter('bubble')` | 남은 알이 연달아 터지고 **납작해진 비닐 시트만 남는다**(구멍·파편 없음) |
| `step('sand')` | `IMPACT.grain` — 튀는 알갱이 + **피어오르는 가루** + 바닥을 스치는 먼지 고리 |
| `step('leaf')` | `IMPACT.leafFly` — **잎사귀가 팔랑이며 날린다**(sway) + 잔부스러기 |
| `whoosh(power)` | `Particles.trail()` — 도약 궤적 |
| (문제 완성) | `Particles.celebrate()` + 정답 칸마다 0.11초 간격으로 도장이 연달아 찍힘 |
| `wrong()` | 붉은 링 + `THUD…` + 화면 흔들림 + 캐릭터 멈칫 |
| (재질별) | `Particles.IMPACT[fx]` — press/puff/jiggle/goo/chunk/pop/balls/grain/sparkleRing/flake |
| (모든 착지) | 타일에 밟은 자국(`t.mark`)이 남아 서서히 사라짐 |
| 파괴 / 완성 | 화면 전체 플래시 + `Particles.tileBreak()` 네 조각 + 어두운 구멍 |
| (모든 소리) | 캐릭터 오라 링 — `Audio.getLevel()` 실시간 RMS로 맥동 |

## 7. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 아무 소리도 안 남 | 브라우저 자동재생 정책. **"산책 시작하기" 버튼을 눌러야** `AudioContext`가 열립니다 |
| 좌우 구분이 안 됨 | 이어폰/헤드폰을 쓰세요. 스피커에서는 HRTF 효과가 크게 줄어듭니다 |
| 샘플이 적용 안 됨 | 콘솔의 `[audio]` 로그 확인 → 404거나 디코딩 실패. `file://`에서는 `fetch`가 막히므로 로컬 서버로 여세요 |
| 소리가 지직거림 | 샘플 피크가 0dBFS에 붙어 있는 경우. −6dBFS로 정규화 |
| 발소리가 늦게 들림 | 샘플 앞부분의 무음 구간을 제거하세요 |
