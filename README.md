# 소리 콩콩 학습 산책

떨어져 있는 타일 사이를 콩콩 뛰어다니며, 한국사 문제의 답을 **한 글자씩 순서대로** 밟는
2D 아이소메트릭 ASMR 학습 게임.

빌드 도구·의존성 없음. 브라우저만 있으면 됩니다.

---

## 실행

```bash
python -m http.server 5178
```

→ http://localhost:5178 접속 후 **"산책 시작하기"** 클릭
(브라우저 자동재생 정책 때문에 클릭 한 번이 반드시 필요합니다.)

`index.html`을 더블클릭해 `file://`로 열어도 동작합니다 — 이때는 내장 폴백 문제 데이터를 씁니다.

**이어폰 착용을 권장합니다.** 캐릭터의 화면 좌우 위치에 따라 HRTF 바이노럴로 정위됩니다.

웹 배포는 [`docs/DEPLOY.md`](docs/DEPLOY.md) 참고 (GitHub Pages 워크플로 포함).

### 조작

**방향만으로는 움직이지 않습니다.** 방향으로 조준한 뒤 점프 버튼을 눌러야 이동합니다.

| 입력 | 동작 |
|---|---|
| 가상 조이스틱 (좌하단) / `W A S D` · 방향키 | 8방향 **조준만** — 갈 곳이 청록 점선으로 깜빡입니다 |
| `Q` `E` `Z` `C` · 넘패드 `7` `9` `1` `3` | **대각선을 키 하나로** 조준 (↖ ↗ ↙ ↘) |
| `쿵` 버튼 (우하단) / `Space` · `Enter` · `J` `K` `F` · 넘패드 `0` `5` `Enter` `+` · 오른쪽 `Shift` `Ctrl` `.` `/` | 조준한 칸으로 **점프** |
| ☰ 메뉴 → **입력 진단** | 브라우저에 실제로 도착한 키를 화면에 그대로 보여 준다 |
| 조준 없이 점프 | 제자리에서 **강하게 내려찍기** (파괴력 2배) |
| ☰ 메뉴 (우상단) | 랭킹 보기 · 소리 끄기 · 조이스틱 켜기/끄기 · 입력 진단 · **소리 도감**(보는 표) |

조이스틱이나 방향키를 잡으면 착지할 타일에 **청록 점선**이 흐르며 깜빡이고,
바깥으로 링이 퍼져 나갑니다. 어디로 뛸지 확인한 뒤 누를 수 있습니다.
눈·모래처럼 윗면이 흰 타일에서도 보이도록 어두운 밑선과 흰 꼭짓점 표식을 함께 깝니다.

조이스틱은 **손가락이 처음 닿은 자리**가 원점입니다(플로팅 스틱). 패드 가장자리를
짚어도 그 방향이 곧바로 입력되지 않고, 손가락이 반경 밖으로 나가면 원점이 따라갑니다.
스틱을 밀면 패드 위에 **어느 칸이 잡혔는지 청록 점**으로 표시됩니다.

방향 판정은 화면상 45°가 아니라 **실제 아이소메트릭 각도**(±26.6°/±90°/0°/180°)로
합니다. 눈에 보이는 타일 쪽으로 밀면 그 타일이 잡힙니다.

키보드 방향 입력은 **가로·세로 축을 따로** 계산합니다. 축마다 "지금 눌려 있는 키"가
우선이고, 눌린 키가 없는 축만 "방금 톡 누른 키 하나"로 채웁니다. 축마다 하나만
기억하므로 `←`와 `→`가 함께 쌓여 서로 상쇄되는 일이 없습니다 — 예전에는 방향키를
마구 누르면 실제로 그렇게 조준이 0에 갇혀 **점선이 사라지고**, 그 상태로 점프하면
제자리 내려찍기가 됐습니다.

**점프 입력은 버려지지 않습니다** — 예전에는 도약 중(0.30초, 큰 점프 0.44초)에 누른
점프가 통째로 사라졌습니다. 연달아 움직이는 동안에는 상당 시간이 '못 뛰는 구간'이라,
플레이어에게는 "가끔 스페이스가 안 먹는다"로 보였습니다. 지금은 뛸 수 있게 되는
순간까지 요청을 들고 있다가 발동합니다.

**세 키를 동시에 누르지 않아도 됩니다** — 대각선 + 점프는 `↑`+`←`+`Space` 로 3키
동시입력입니다. 값싼 멤브레인 키보드는 3키 롤오버를 전부 받지 못하고, 막히는 조합은
키 매트릭스 배선마다 다릅니다(방향키 묶음에서 특히 자주 일어납니다). 그래서
"WASD로는 되는데 방향키로는 왼쪽 위만 안 된다"가 실제로 생깁니다. 대비책이 둘입니다.

1. **톡톡 이어 누르면 대각선 조준이 됩니다.** `↓` 톡 `→` 톡 처럼 이어 누르면
   가로·세로를 각각 기억해 합칩니다. 조준을 잡은 뒤 점프 키를 누르면 되므로
   한 번에 눌리는 키가 둘을 넘지 않습니다.
2. **`Q E Z C`**(넘패드 `7 9 1 3`)는 키 하나가 대각선 하나입니다.
3. **점프 키도 여러 개** 깔려 있습니다 — `Space` `Enter` `J` `K` `F`,
   오른쪽 `Shift` `Ctrl` `.` `/`, 넘패드 `0` `5` `Enter` `+`.

> **방향만으로는 절대 움직이지 않습니다.** 방향은 조준일 뿐이고, 점프 키를 눌러야
> 이동합니다. 이 규칙은 게임의 핵심이라 어떤 대비책도 이걸 깨지 않습니다.

**조준과 점프를 동시에 눌러도 됩니다.** 사람은 두 키를 정확히 같은 순간에 누르지
못해서, 방향이 몇 ms만 늦어도 그 프레임이 '방향 없음'이 되어 제자리 내려찍기로
끝나 버렸습니다. 지금은 **조준이 없을 때만** 점프 판정을 0.13초 미루고 방향을
기다립니다. 조준이 이미 있으면 한 프레임도 기다리지 않으므로 반응은 그대로입니다.

**그래도 안 되면 ☰ 메뉴 → 입력 진단**을 켜 보세요. 브라우저에 **실제로 도착한 키**를
그대로 보여 줍니다. `Space` 를 눌렀는데 목록에 안 뜨면 키보드가 그 키를 삼킨 것이고
(게임이 손쓸 수 없는 영역입니다), 뜨는데도 안 움직이면 게임 쪽 문제입니다.
둘은 화면만 봐서는 구별할 수 없어서 이 패널을 붙였습니다.

제자리 내려찍기와 헷갈릴 일은 없습니다 — **조준 표시가 켜져 있으면 그 칸으로,
꺼져 있으면 내려찍기**입니다. 화면에 보이는 그대로입니다.

## 게임 규칙

타일은 서로 **한 칸씩 떨어져 떠 있고**, 캐릭터는 타일에서 타일로 점프합니다.

**보드에는 빈 칸(구멍)이 있습니다.** 빈 칸으로 뛰면 떨어져서 **점수 15점을 잃고**
직전 발판으로 돌아옵니다. 그래서 어디로 뛸지가 선택이 됩니다 — 빈 칸을 조준하면
**붉은 점선과 아래 화살표**로 미리 경고합니다.

구멍은 판을 만들 때마다 무작위로 뚫리지만 두 가지를 반드시 지킵니다 —
시작 칸은 절대 구멍이 아니고, 남은 타일은 **전부 하나로 이어져 있습니다**(섬이
생겨 문제 글자를 영영 못 밟는 판이 만들어지지 않도록). **구멍끼리 맞닿게 뚫지도
않습니다** — 두세 칸이 이어져 비면 건너뛸 수 없는 벽이 생깁니다. 문제 글자도 구멍에는
놓이지 않습니다. 보드 밖으로는 나갈 수 없습니다.

**한 타일에는 한 글자만** 올라갑니다. 답이 `경상북도`라면
`경` → `상` → `북` → `도` 네 타일을 순서대로 밟아야 합니다.

- 한 글자 맞을 때마다: 상승하는 펜타토닉 `톡-톡` + 별빛 + `TOK!` + 초록 파문
- 마지막 글자 완성: `CRACKLE-POP!` `PERFECT!` + 아르페지오 + 팝 14연발
- 순서를 틀리면: 둔탁한 thud, 화면 흔들림, 0.6초 멈칫, **진행 전체 리셋** (−5점, 목숨 −1)
- 빈 칸에 떨어지면: **−15점**, 0.55초 멈칫, 직전 발판으로 복귀 (목숨 −1)
- 발판이 부서져 떨어지면: 위와 같음 (목숨 −1)
- **두 실패는 소리가 다릅니다.** 오답은 벽에 부딪힌 것처럼 가깝고 짧고 건조하게
  (F3→C3 두 계단), 추락은 소리가 나를 두고 아래로 멀어지듯 길고 젖게
  (196→49Hz 미끄러짐 + 스치는 공기). 둘 다 어둡고 아래로 내려가서 '잘못됐다'로
  들리지만, 무엇을 잘못했는지는 **화면을 보기 전에 귀로 먼저** 알 수 있습니다

### 목숨과 게임 오버

HUD 오른쪽에 **하트 5개**로 남은 목숨이 표시됩니다. 셋 중 하나라도 일어나면
하트가 하나 줄고, 잃은 자리에 💔 가 튀어오릅니다.

| 목숨을 잃는 경우 |
|---|
| 답을 **틀렸을 때** |
| **빈 칸**에 빠졌을 때 |
| 밟은 **발판이 부서져** 떨어졌을 때 |

셋 다 "발밑이 무너지거나 길을 잘못 들었다"는 같은 종류의 실패라서 같은 값을 냅니다.
뒤의 둘은 코드에서도 `fallIntoHole()` 한 군데로 모입니다.

하트를 전부 잃으면 **게임 오버** — 최종 점수와 함께 화면이 뜨고, `다시 시작하기`를
누르면 점수·목숨·보드·문제가 전부 새로 만들어집니다.
- 밟은 타일이 **부서지면 그대로 아래로 빠집니다** — 구멍에 떨어진 것과 같은 **−15점**
- 2회 틀리면 문제 아래에 글로 된 힌트가 켜집니다 (정답 타일을 직접 알려 주지는 않습니다)
- 이미 밟은 타일을 다시 지나가는 것은 실수로 처리되지 않습니다
- 글자 타일은 밟는 순간 판정되므로 **지나가는 길이 될 수 없습니다.** 그래서 글자가 없는
  디딤 타일로 이어진 **길**이 하나 있고, 캐릭터와 모든 글자가 그 길에 맞닿도록 배치합니다 —
  "오답을 밟지 않고는 다음 글자로 갈 수 없는 판"이 만들어지지 않습니다
- **한번 부서진 타일은 그 문제 안에서는 되살아나지 않습니다.** 대신 그 위의 글자가 성한 칸으로
  이사하고, 그 자리가 사라지면 판이 끊기는 타일은 아예 부서지지 않습니다 — 답을 못 밟는 판은
  만들어지지 않습니다
- **문제가 바뀌면 판을 새로 깝니다.** 재질도 구멍 배치도 새로 정해지고, 앞 문제에서 부서진
  자리·금·발자국은 남지 않습니다. 예전에는 한 게임 내내 같은 타일을 써서 풀수록 발판이 줄었고,
  뒤에 나온 문제일수록 불리했습니다 — 이제 모든 문제가 같은 조건에서 시작합니다
- **한 문제에 쓰는 재질은 두 가지뿐입니다** — 글자 타일 한 종류, 나머지 바닥 한 종류.
  판을 새로 깔 때마다 바닥이 바뀌어서, 한 판을 도는 동안 18종을 다 만나되 만나는 동안에는
  끊기지 않습니다

### 타일 — 보면 무슨 소리가 날지 안다

재질마다 색·두께·표면 구조가 전부 달라서, 밟기 전에 소리를 예상할 수 있습니다.
메뉴의 **소리 도감**에서 타일 그림·소리·부서짐 여부를 표로 볼 수 있습니다.

한 문제 안에서는 **재질이 두 가지뿐**입니다. 예전에는 칸마다 해시를 돌려 18종을
흩뿌렸는데, 한 발짝 옮길 때마다 소리가 바뀌니 ASMR이 아니라 **효과음 모음집**이
됐습니다. 한 재질에 몸을 담그려면 그 소리가 연달아 나야 합니다. 대신 문제마다
바닥을 갈아 끼우고, 가방에서 뽑아 쓰고 비면 다시 섞는 식이라 한 재질만 계속 나오거나
계속 빠지는 일은 없습니다.

| 타일 | 생김새 | 소리 | 밟으면 |
|---|---|---|---|
| 키캡 | 오목한 상판 + 도톰한 테두리 + 스쿱 반사 | **톡** | 눌렸다 스프링 복원 |
| 솜 | 부푼 덩어리 네 개 + 보송한 솜털 | **포옥** | 깊게 눌리고 천천히 복원 |
| 젤리 | 반투명 + 큰 광택 + 안쪽 기포 | **통** | 크게 출렁이며 복원 |
| 나무 | 널판 이음새 + 나뭇결 + 못 자국 | **탁** | 살짝 눌림 |
| 슬라임 | 가장자리에서 흘러내리는 가닥 + 떠오르는 기포 | **찌걱** | 끈적하게 늘어졌다 복원 |
| 유리구슬 | 투명 구슬 + 십자 반사 | **챠랑** | 맑게 오래 울림 |
| 스펀지 | 숭숭 뚫린 구멍 | **뽀드득** | 공기를 머금었다 내뱉음 |
| 물웅덩이 | 고인 물 + 끊임없이 번지는 잔물결 | **찰방** | 방울이 튀고 파문이 남음 |
| 자갈 | 물에 닳아 둥글고 맨들맨들한 조약돌이 수북이 | **자그락** | 돌이 서로 부딪히며 밀림 |
| 양철판 | 골이 진 함석 + 못머리 | **탱** | 판이 울리며 파문이 세 겹 |
| 낙엽 | 잎맥까지 그린 잎사귀 (밟을수록 줄어듦) | **바스락** | **4번째**에 부서짐 · 영구 · 밟으면 잎이 팔랑이며 날린다 |
| 에어캡 | 볼록한 돔 7개 (터진 자리는 주름) | **뽁** | 밟을 때마다 **알이 2개씩 터진다** · 4번째에 전부 터짐 · 영구 |
| 구슬볼 | 말랑한 색색 구슬 (밟을수록 사라짐) | **톡톡** | **4번째**에 부서짐 · 영구 |
| 모래 | 끊긴 잔물결 능선 + 세 톤 알갱이 + 눌린 웅덩이 | **사각** | **4번째**에 부서짐 · 영구 · 밟으면 가루가 피어오른다 |
| 눈 | 푸른 그늘의 소복한 둔덕 + 깜빡이는 결정 + 다져진 자국 | **뽀득** | **4번째**에 부서짐 · 영구 |
| 종이 | 어긋나게 겹친 낱장 (밟을수록 구겨짐) | **구깃** | **4번째**에 부서짐 · 영구 |
| 쿠키 | 구운 반죽 + 박힌 초코칩 (밟을수록 조각이 떨어짐) | **바삭** | **4번째**에 부서짐 · 영구 |
| 얼음 | 속이 비치는 판 + 갇힌 기포 + 결빙선 | **쩌억** | **4번째**에 부서짐 · 영구 |

### 밟았을 때의 시각 효과

소리마다 짝이 되는 연출이 다릅니다. 재질을 보고 소리를 예상하고, 밟으면 그 예상이 눈으로도 확인됩니다.

| 재질 | 임팩트 연출 |
|---|---|
| 키캡 | 먼지가 낮게 튀고 표면이 짧게 발광 |
| 나무 | 먼지가 바닥을 따라 밀려 나가고 판이 한 번 울림 |
| 솜 | 부드러운 구름이 부풀어 오름 |
| 스펀지 | 구멍에서 공기 줄기가 뿜어 나옴 |
| 젤리 | 잔상 링 세 겹이 연달아 퍼짐 |
| 슬라임 | 실처럼 늘어졌다 끊어지는 가닥 |
| 낙엽 | 각진 파편이 회전하며 튐 |
| 에어캡 | 사방으로 뻗는 섬광선 |
| 구슬볼 | 색색 구슬이 통통 튀며 굴러 나감 |
| 모래 | 아주 작은 알갱이 30여 개가 낮게 흩어짐 |
| 유리구슬 | 십자 섬광 + 반짝이 |
| 눈 | 눈 결정이 흩날림 |
| 물웅덩이 | 물방울이 높이 튀고 동심원 파문이 남음 |
| 자갈 | 돌이 튀어 굴러 나가고 마른 먼지가 인다 |
| 종이 | 얇은 조각이 팔랑이며 떠다님 |
| 쿠키 | 부스러기가 사방으로 튀고 초코칩이 굴러 나감 |
| 양철판 | 링이 세 겹 퍼지고 때린 자리에 섬광 |
| 얼음 | 균열선이 곧게 뻗고 냉기와 조각이 흩어짐 |

**소리와 눈을 같은 사건으로 묶는 두 가지**

- 밟은 자리에서 **표면을 가로지르는 파문**이 번집니다. 소리는 한 점에서 퍼져 나가는
  것인데 타일 전체가 한꺼번에 밝아지기만 하면 그 감각이 사라집니다.
- 그 파문과 발광이 **재질의 소리 꼬리만큼** 남습니다. 유리구슬(1.1초)·얼음(0.75초)·
  양철판(0.72초)은 길게 여운이 남고, 키캡(0.14초)·나무(0.2초)는 탁 끊깁니다.
  이 값은 눈대중이 아니라 실제 소리의 감쇠를 재서 맞춥니다 — 양철판은 녹음을 넣으면서
  0.95초에서 0.72초로 줄였습니다(녹음의 −30dB 지점이 0.32초).

여기에 더해 **모든 타일에 공통으로**:

- 밟은 자리에 **자국**이 남아 서서히 사라집니다 (모래·눈은 발자국, 슬라임·구슬볼은 젖은 얼룩, 나머지는 눌린 그림자)
- 소모성 타일은 단계마다 **균열선이 늘고 살짝 기울어지며**, 표면의 장식이 줄어듭니다
  (잎이 사라지고, 에어캡 알이 터지고, 구슬이 없어짐)
- 완전히 부서지면 윗면이 **네 조각으로 갈라져 날아가고**, 그 자리에 어두운 구멍이 남습니다.
  구멍 테두리에는 그 재질의 색 조각과 가루가 남아, 무엇이 부서진 자리인지 알아볼 수 있습니다
- 파괴·정답 완성 순간에는 **화면 전체가 재질 색으로 번쩍입니다**
- 캐릭터 주변 오라 링은 실제 출력 레벨(RMS)에 맞춰 맥동합니다

남은 횟수는 타일 아래 흰 점으로 표시됩니다. 소모성 타일은 **세 번까지 버티고 네 번째에** 부서지며,
세게 내려찍어도 한 번은 한 단계입니다.
완전히 부서진 자리는 **영영 구멍으로 남습니다.** 다만 그 자리가 사라지면 판이 두 조각으로
끊기거나 성한 발판이 10칸 아래로 줄어드는 타일은, 다 금이 간 채로 버티고 부서지지 않습니다.

## 구현된 시스템

**조준 후 점프** — 방향 입력은 8방향으로 양자화되어 착지할 타일을 **표시만** 하고,
점프 입력이 들어와야 포물선 도약이 시작됩니다. 점프 입력은 '눌림 유지' 방식이라
먼저 조준하고 눌러도, 누른 채 조준을 바꿔도 의도대로 뜁니다.
연속으로 뛸수록(체인) 착지 강도가 올라가 소리의 피치와 음량이 커집니다.

**파묻힘 없는 착지** — 캐릭터는 매 프레임 발밑 타일의 **실제 윗면 높이**(`Tiles.surfaceOffset`)를
따라갑니다. 재질마다 두께가 다르고 눌림·파손으로 높이가 변해도 발이 항상 표면에 붙습니다.

**소리 ↔ 시각 결합** — 모든 사운드 호출은 짝이 되는 시각 효과를 함께 냅니다.
재질별 팔레트(`Particles.PALETTE`)가 오디오 재질 키와 1:1로 대응하고,
타일은 소리와 함께 표면이 발광하며, 캐릭터 주변 오라 링은
`AnalyserNode`로 측정한 **실제 출력 레벨**에 맞춰 맥동합니다.

**다단계 파괴** — 소모성 타일은 밟을 때마다 균열이 누적되고 소리가 단계별로 밝아집니다
(`Audio.crack(mat, stage, total)`). 마지막 타격에서만 완전히 부서집니다.

**겹치지 않는 레이아웃** — `safeRect()`가 HUD와 조이스틱의 실제 DOM 위치를 측정해
남는 공간을 계산하고, 보드를 그 안에 맞춰 스케일·중앙 정렬합니다.
세로 여유가 부족한 납작한 태블릿에서는 자동으로 컨트롤 *사이* 공간을 씁니다.
화면 폭에 따라 격자도 4×4 / 5×5 / 6×6 으로 바뀝니다.

**모달 합성 기반 ASMR 오디오** — 두드린 물체는 "감쇠하는 공명 모드의 합"이라는
물리 모형을 그대로 구현했습니다. 재질마다 고유한 비조화 배음비(예: 나무 1 : 2.37 : 5.38 : 9.12)를
가진 3~5개 모드를 쌓고, **트랜지언트 / 바디 / 테일** 3단으로 나눠 합성합니다.
낙엽·모래·눈처럼 공명이 없는 재질은 수십 개의 미세 알갱이를 시간·주파수·좌우로 흩뿌리는
**그래뉼러 텍스처**로 만들고, 눈·스펀지의 '뽀득'은 좁은 대역이 위로 쓸려 올라가는 공명 처프로 만듭니다.
매 타격마다 피치·타이밍·게인이 조금씩 흔들려(휴머나이즈) 기계적 반복이 없고,
잔향은 짧고 어둡게(0.85초) 두어 근접 마이크 감각을 살렸으며, 마스터에 리미터가 걸려 있습니다.
오디오 파일은 여전히 **0개**입니다.

## 문제 추가

`data/quizzes.json`을 편집한 뒤:

```bash
python tools/build-fallback.py
```

검증(에러/경고)과 `file://`용 폴백 사본 생성이 함께 이뤄집니다.
스키마 전체는 [`docs/DATA_PIPELINE.md`](docs/DATA_PIPELINE.md)를 보세요.

현재 기본 문제집: **한국사 50문항** · 타일 재질 **18종**

| 단원 | 문항 | 범위 |
|---|---|---|
| 선사·고조선 | 20 | 구석기~철기, 고조선 건국과 8조법 |
| 삼국·가야 | 15 | 삼국의 성립, 전성기 왕과 비석, 가야 연맹 |
| 생활·문화 | 15 | 신분과 의식주, 불교, 대외 교류 |

문제는 **순서 없이 무작위로 무한 반복** 출제됩니다.
한 바퀴(50문항)를 다 돌면 다시 섞어 출제하므로 같은 문제가 한쪽으로 몰리지 않고,
직전 문제가 곧바로 다시 나오는 일도 없습니다.
단원을 골라 푸는 기능은 일부러 두지 않았습니다 — 문제가 언제나 전체에서
무작위로 나와야 모두가 같은 조건으로 겨룰 수 있기 때문입니다.
(랭킹 화면에서 단원별로 **보는** 것은 됩니다.)

## 이어하기

하던 판은 저절로 저장됩니다. 창을 닫았다 다시 들어와도, 다른 화면으로 옮겼다
돌아와도 이어서 할 수 있습니다.

담기는 것은 판 전체입니다 — 점수·목숨·시간, 타일 하나하나의 재질과 닳은 정도,
글자 배치, 지금 문제와 어디까지 밟았는지, 앞으로 나올 문제 차례, 선 자리.
저장은 이 브라우저 안(`localStorage`)에만 있으므로 기기를 옮기면 따라오지 않습니다.

- 시작 화면에 **이어서 산책하기 / 처음부터 새로 시작** 이 함께 나옵니다.
- 저장 시점은 문제가 바뀔 때, 목숨을 잃을 때, 착지할 때(0.9초에 한 번),
  그리고 화면을 숨기거나 닫는 순간입니다.
- 게임 오버가 나면 저장은 지워집니다. 일주일이 지난 저장도 잇지 않습니다.
- 문제집을 갈아 끼웠거나 저장이 앞뒤가 맞지 않으면 조용히 새 판으로 시작합니다.

저장된 판은 언제나 조용한 `play` 상태로 되살아납니다. 도약 중이거나 정답 연출
중이던 순간까지 복원하려다 반쯤 끝난 연출에 갇히는 쪽이 훨씬 나쁘기 때문입니다.

## 플레이 시간

HUD 에 `0:00` 으로 표시되고, 기록(시트)에 남습니다.

세는 것은 **실제로 논 시간**입니다. 탭을 숨기거나 창을 옮기면 브라우저가
`requestAnimationFrame` 을 멈추므로 시계도 저절로 같이 멈춥니다 — 켜 두고
자리를 비운 시간은 기록에 들어가지 않습니다.

**랭킹 조건은 아니다.** 제한 시간이 없는 게임이라 켜 두기만 해도 늘어나기
때문입니다. 대신 '시간에 비해 점수가 너무 높지 않은가' 같은 조작 검사에 쓰입니다.

## 랭킹

구글 스프레드시트에 기록을 모읍니다. 설치는 10분이면 되고,
방법은 [`docs/RANKING.md`](docs/RANKING.md) 에 처음부터 끝까지 적어 두었습니다.

**설정하지 않아도 게임은 그대로 돌아갑니다.** 그때는 기록이 그 기기 안에만 남고,
랭킹 화면이 설정이 필요하다고 알려 줍니다.

### 집계 조건

**단원 × 지표** 두 단으로 고릅니다.

| 지표 | 무엇을 겨루나 | 집계 | 참가 조건 |
|---|---|---|---|
| 점수 | 한 판에서 얼마나 연달아 맞혔나 | **한 판 최고** | 없음 |
| 맞힌 문제 | 끝까지 푼 문제 수 | 모든 판 누적 | 없음 |
| 시도 문제 | 얼마나 많이 도전했나 | 모든 판 누적 | 없음 |
| 정답률 | 시도한 문제 중 맞힌 비율 | 모든 판 누적 | **시도 30문제 이상** |
| 밟기 정확도 | 밟은 타일 중 순서에 맞았던 비율 | 모든 판 누적 | **시도 30문제 이상** |

정답률이 '내용을 아는가'라면 밟기 정확도는 '발을 정확히 디뎠는가'입니다.
두 값을 나란히 보면 막힌 곳이 내용인지 조작인지 구분됩니다.

단원(선사·고조선 / 삼국·가야 / 생활·문화)을 고르면 그 단원의 **맞힌 문제**와
**정답률**만 남고, 둘 다 **그 단원을 30문제 이상 시도한 사람**만 들어갑니다.

점수만 '한 판 최고'인 것은 콤보를 이은 한 판의 성적이기 때문이고, 나머지는
"얼마나 많이, 얼마나 정확하게 공부했나"라서 여러 판을 누적합니다.
30문제 기준은 3문제 중 3개 맞힌 100%가 100문제 중 92개 맞힌 92%를 이기는 일을
막기 위한 것입니다.

**시도 문제는 글자를 한 번이라도 밟은 문제만** 셉니다. 받아 놓고 손도 대지 않은
문제(게임 오버 직전에 뜬 문제 등)는 시도가 아니니까요.
한 문제에서 여러 번 틀려도 시도는 1회입니다.

**문제를 건너뛰거나 단원을 골라 풀 수는 없습니다.** 모르는 문제를 넘길 수 있으면
시도 수를 부풀리고 어려운 문제를 피해 정답률을 올릴 수 있습니다. 나온 문제는
풀거나 틀리거나 둘 중 하나입니다.

네 지표 모두 **높은 순·낮은 순** 으로 볼 수 있고, 화면에는 **100위까지**,
그 아래는 **닉네임 검색**으로 찾습니다.

### 닉네임과 개인정보

닉네임은 누구나 보는 목록에 그대로 올라갑니다. 그래서 두 겹으로 막습니다.

1. 기계가 알아볼 수 있는 것(이메일·전화번호·주민등록번호 꼴·학년/반/번호·긴 숫자)은
   게임과 서버 양쪽에서 각각 거릅니다.
2. 사람 이름은 기계가 가려낼 수 없으므로("홍길동"과 "달려라곰"은 구별되지 않습니다)
   경고문을 띄우고 **확인란에 체크해야만** 등록 버튼이 켜집니다.

### 조작 방지

기준은 실제 플레이의 **두세 배로 넉넉하게** 잡았습니다. 잘하는 아이가 억울하게
걸리는 쪽이 부정행위 한 건이 지나가는 쪽보다 나쁘기 때문입니다.

- 점수·목숨·시간은 클로저 안에만 있어 콘솔에서 값을 고칠 수 없습니다.
- 테스트용 훅(`SK.Game.debug`)은 `localhost` 와 `?debug=1` 에서만 열리고,
  쓰면 그 판은 비공식으로 표시되어 랭킹에 올라가지 않습니다.
- 등록에는 서버가 발급한 **1회용 실행 토큰**이 필요하고, 보낸 값에는 서명이 붙어
  네트워크 탭에서 숫자만 고치면 거부됩니다.
- 서버는 시간·점수·문제 수의 앞뒤가 맞는지 봅니다.
- **걸린 기록도 지우지 않습니다.** 시트에 남고 `공개` 칸만 `FALSE` 가 되며 이유가
  적힙니다. 정상인데 걸렸다면 선생님이 `TRUE` 로 바꾸면 바로 올라갑니다.

게임 파일을 통째로 고친 사람까지는 막지 못합니다 — 브라우저에서 도는 코드는
원래 그렇습니다. 마지막 판단은 시트를 보는 선생님의 몫으로 남겨 두었습니다.

## 자동 테스트용 훅

```js
SK.Game.debug.state()          // 페이즈, FSM 상태, 기대 토큰, 타일(재질·균열 포함)
SK.Game.debug.stepOn(i,j,power) // 해당 타일에 착지 (power 2 = 큰 점프)
SK.Game.debug.tick(dt)          // 탭이 숨겨져 rAF가 멈춰도 한 프레임 진행
SK.Game.debug.safeRect()        // HUD·조이스틱을 뺀 보드 배치 영역
SK.Game.debug.boardBounds()     // 실제로 그려진 보드의 화면 경계(겹침 점검용)
SK.Game.debug.aimCount()        // 조준 표시가 켜진 타일 수
SK.Audio.preview('leaf')        // 재질 소리 미리듣기 (개발용 — 도감에서는 소리가 나지 않는다)
SK.Audio.envelope(fn, 1500)     // 소리 하나의 K-가중 포락선 — 실패음 모양 비교는 이걸로
SK.Audio.getLevel()             // 실시간 출력 레벨(0~1) — 화면 연출용 피크 미터
SK.Audio.loudnessTable()        // 18종 체감 음량(K-가중) 측정 — 음량 밸런스는 이걸로
SK.Audio.peak()                 // 마스터 출력 순간 피크 — 헤드룸 확인
SK.Game.debug.input()           // 방향키 상태·조준 버퍼·조준 방향 (입력 문제 진단용)
SK.Game.debug.keyLog(true)      // 키 이벤트가 실제로 도착하는지 콘솔에 찍기
SK.Game.debug.matOf(i,j)        // 그 칸의 재질
SK.Game.debug.setMat(i,j,mat)   // 재질 바꾸기 — 특정 재질 연출 확인용
SK.Game.debug.matMix()          // 지금 판에 깔린 재질과 칸 수 — kinds 는 늘 2여야 한다
SK.Game.debug.snapshot()        // 지금 판의 저장 스냅샷 (이어하기 확인용)
SK.Game.debug.save()            // 지금 즉시 저장
SK.Game.getTimeMs()             // 이 판의 플레이 시간(ms)
SK.Game.getRunRecord()          // 랭킹에 올릴 한 판의 요약
SK.Game.isTainted()             // 이 판이 테스트용 훅에 손댔는가
SK.Save.summary()               // 저장된 판 한 줄 요약
SK.Ranking.validateNick('...')  // 닉네임 검사 결과
```

> `SK.Game.debug` 는 `localhost` 이거나 주소에 `?debug=1` 이 붙었을 때만 있습니다.
> 배포된 주소에서 열려 있으면 랭킹이 의미를 잃기 때문입니다.
> 판을 바꾸는 훅(`stepOn`·`tick`·`press`·`release`·`setMat`)을 쓰면 그 판은
> 비공식으로 표시되어 랭킹에 올라가지 않습니다.
